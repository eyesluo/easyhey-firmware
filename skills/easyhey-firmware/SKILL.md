# 固件羊 API 固件管理

默认使用本 skill 的 [API 客户端](scripts/easyhey-api.mjs)，在持久 JavaScript 会话中直接请求后台。**不再通过网页点击、填表或文件选择器上传、修改和发布**。若接口不兼容，报告具体阻碍并修正客户端；不要静默退回网页上传。默认用中文汇报。

## 开始

1. 阅读 [API 操作](references/api.md)，加载客户端，调用公开的 `chips()` 核实连接与芯片 ID。
2. 在同一持久会话中复用已认证的客户端。没有会话或已过期时按 [扫码登录](references/connection.md) 先检查渲染依赖，再获取并校验二维码；实际展示图片并附可点击的备用图片链接后，请用户扫描。等待扫码的最终回复也必须包含图片和链接，不能仅输出路径或说“见上方”。随后用 API 确认身份。网页已登录不代表 API 客户端已登录。
3. 查询调用 `list()`、`detail(id)`；修改调用 `updateInfo()`；上下架调用 `setPublished()`。
4. 上传发布先 `inspectManifest()` 本地校验，再 `uploadFile()` 上传，最后 `preparePublish()` 生成提交内容、`publish()` 创建并核验。
5. 删除调用 `deleteFirmware()`，提供已定位目标的准确名称、版本及独立操作记录；删除后核验列表中已不存在该 ID。

官方 MCP 是可选的另一种 API 通道，仅在用户指定 MCP 或当前连接满足请求时参阅 [MCP 操作](references/mcp.md)。不要用后台 API 绕过已发起的 MCP 确认流程。MCP OAuth 与本客户端扫码会话不混用。

## 授权与执行边界

- “修改 skill”“检查接口”不授权上传文件、创建固件或改变发布状态；此类工作只运行本地测试及公开只读查询。
- “暂不发布”立即停止提交；若用户也没有要求继续上传，则连上传也停止。下一次发布需要用户明确恢复该请求，不能由旧计划自动续发。
- `uploadFile()` 只上传文件；`publish()` 完成创建、必要的固件码绑定和发布核验。实测创建接口可能返回 status=0、无固件码的记录，必须再调用 `/firmware/share/bind` 才发布。仅要求新建草稿时保存本地计划；当前不单独暴露远程草稿创建方法。只允许上传时停在文件回执。
- `execute:true` 是脚本防误调用开关，不是用户授权。只有当前会话已经授权具体动作才传入；已有明确授权时不重复询问。
- 通过列表定位内部 ID，固件码和版本号不可当 ID 使用。同名同版本不明确时先消歧。
- 名称/描述修改使用最小字段 PATCH，并同步更新描述中的更新时间；保留其他字段。默认客户端不提供烧录密码、授权数量或互换固件码操作。
- 删除需用户明确要求删除目标，或明确要求对专用临时测试记录验证删除能力。准确定位 ID、名称、版本后执行，不批量扩大范围；已有明确授权无需重复确认。删除不自动重试，不删除底层上传文件（可能被其他固件复用）。
- 测试线上管理能力时使用明确命名的临时记录，记录测试前后状态并在结束后删除；不要用正式固件验证编辑、暂停或删除。测试未完成时报告临时记录的 ID 和剩余清理步骤。

## 凭据

访问令牌、刷新令牌、扫码场景和上传凭证只保存在客户端私有内存。不要输出、导出或写入仓库/日志，不读取浏览器 Cookie、localStorage 或浏览器配置文件来代替 API 登录。无需用户复制凭据，也不使用管理员/service-role 密钥。

API 的公开 publishable key 是官网前端配置，不是用户登录凭据。登录失效时重新扫码；权限错误不改用其他账号，不绕过行级权限。

## 文件与烧录配置

从实际构建产物确定版本、芯片、文件和烧录地址。源码配置与现成二进制不同时，应指出差异，优先解析将要上传的镜像和分区表；不能拿源码版本冒充固件内版本，也不能把教程地址套到用户文件。

收集名称、描述、实际版本、`chips()` 返回的芯片 ID、文件绝对路径、每个文件的地址、擦除策略与自动重启选项。不要把 ESP32-S3 镜像头的芯片编号当作网站 chip_id。缺失的芯片/地址不能猜；擦除策略无法确定时询问一次。

每个文件必须非空、为 `.bin` 且不超过 50 MiB。检查 SHA-256、地址重叠及已知闪存容量，结合真实分区表检查分区容量；客户端的通用范围校验不能代替硬件/分区核验。不上传整个工程，不混用其他项目的引导或模型文件。

上传前记录本地摘要；上传后保存不含凭据的回执（路径、大小、SHA-256、etag）。只有文件哈希与回执匹配才能进入发布。

## 提交与结果

新建上传或更新固件时，**必须在固件描述末尾标注本次更新时间**，格式为 `更新时间：YYYY-MM-DD HH:mm:ss（北京时间）`，时区固定为 `Asia/Shanghai`，取实际提交时的当前时间，不使用编译时间、文件修改时间或示例日期。已有独立的更新时间行替换为最新一行，不重复堆叠，保留描述正文。包含时间的完整描述不得超过 500 字符；超限先精简正文，不静默截断。提交后读回核验描述。

客户端 `publish()` 和 `updateInfo()` 自动完成上述标注；即使只修改名称或版本，也会读取原描述并同步更新时间。`inspectManifest()`/`preparePublish()` 预览含时间的描述，正式提交时重新生成时间。若使用其他已核实的 API 或 MCP 更新固件，也须把标注后的描述纳入同一次变更。单独上传文件尚无固件记录时，在后续创建/更新记录时写入；查询和单纯上下架不刷新此时间。

提交前简述名称、版本、芯片、文件/地址、擦除策略与预期状态。用户已授权发布且所有参数明确即可执行，不另加审批流程。

每次发布使用独立的本地 operationFile；先写入记录再调用后台。创建成功返回 ID 后核验详情、文件配置、固件码和实际状态。若创建成功但未绑定，复用该 ID 调用 `bindShareCode()`，不要重跑创建；绑定使用独立的操作记录，结果未知时先查询。发布结果未知时查看记录并重新查询，**不要删除记录、换记录路径或换固件码来盲目重试**。

上传成功不代表已发布；创建响应成功不代表状态已上架。修改使用当前时间戳条件防止覆盖并发修改；冲突时重新读取并重新评估。网络错误和 401/403 不自动重放写请求。

最终报告实际完成动作、名称/ID/版本、状态和固件码；未执行或未验证部分如实说明。接口来自官网部署前端的实测分析，并非承诺长期稳定的公开 REST 契约；验证范围见 API 参考。
