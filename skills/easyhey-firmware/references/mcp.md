# 官方 MCP 操作

核实日期：2026-10-28。来源：[EasyHey MCP 接入](https://easyhey.com/mcp.html)。以下是官方工具用途；以当前服务端暴露的 schema 为准，本文不假设参数字段或响应结构。

端点：`https://easyhey.com/mcp`，Streamable HTTP，微信扫码 OAuth 授权后只管理当前用户固件。

| 目标 | 官方工具名 | 使用要点 |
| --- | --- | --- |
| 列表 | `list_my_firmware` | 支持分页；“全部”必须遍历到末页，单页结果标明范围 |
| 详情 | `get_firmware_detail` | 按固件 ID 查询；修改前后核验 |
| 下载统计 | `get_download_stats` | 全部或指定固件；按实际时间范围、单位汇报，不把下载量称为烧录量 |
| 名称/描述 | `update_firmware_info` | 仅修改请求的字段；先预览再用确认令牌执行 |
| 上架/下架 | `set_firmware_publish` | 两阶段确认；当前状态已满足目标时无需重复操作 |

## 查询

先列表定位再读详情。名称匹配可在读取的结果中筛选，不假设服务端有未声明的搜索参数。使用真实游标或页码，未遍历完不宣称“没有”或“全部”。返回用户需要的名称、ID、固件码、版本、芯片、状态或统计，省略未提供字段。

## 写入两阶段流程

1. 读取详情，构造最小变更。
2. 按当前 schema 请求预览，不臆造 `dry_run`、`confirm` 或令牌字段名。
3. 展示实际预览、目标及变化。官方接口要求用户确认预览后才带令牌执行，因此此处询问确认；不能把预览生成当作同意。用户已确认同一有效预览时无需重复询问。
4. 使用服务端返回的令牌及完全相同的参数执行。令牌仅用于对应操作，不持久化、不展示。
5. 重读详情核验。预览过期、参数改变或目标状态变化时重新生成预览并确认，不复用旧令牌。

确认时说明：“固件羊官方 MCP 接口要求先预览再确认；以下是具体变更。”这是该 MCP 接口的要求，不是为其他 API 操作新增审批规则。

## 能力边界

官方文档未列出新建、上传、修改芯片或分区的工具。新建和上传使用本 skill 的 [API 客户端](api.md)；客户端暂未封装已有固件的芯片/分区修改。未来新增工具先检查真实 schema 和权限。不调用猜测的接口，不通过其他通道绕过 MCP 正在等待的用户确认。

鉴权失败走正常 OAuth；权限不足不换账号或重复写入。工具不可用时可按 [扫码登录](connection.md) 建立独立的 API 客户端会话，但不能声称 MCP 已接通，也不恢复网页表单操作。
